# 页面切换与交互性能

常用页面保留界面和浏览状态，切换时恢复已有页面。曲库和歌单总览在启动后的空闲时间预渲染；其他页面首次访问后保留。具体歌单、歌手、专辑详情最多保留最近使用的 6 个，超过限制时释放较久未使用的详情界面。

隐藏页面通过 React Activity 停止 Effect、进度订阅、绘图和快捷键监听。音频、播放状态保存和系统媒体控制位于页面外，切换页面和进入迷你模式不会重新创建播放器。显示页面时重新连接必要的监听，并使用当前共享数据。

曲库保留搜索、排序、筛选、选择和滚动位置。页面滚动位置分别保存；歌手和专辑目录继续使用原有列表位置恢复逻辑。详情页被释放后不再保留其局部输入和筛选状态。

播放进度使用独立订阅，仅更新进度控件和系统媒体位置；歌词按当前行订阅，不再跟随每次音频进度更新重绘主页面。歌词解析和翻译匹配按内容缓存。歌单通过歌曲 ID 索引解析，避免逐首遍历完整曲库。

超过 200 首歌曲的侧边队列和浮动队列只渲染视口及附近歌曲，保留完整滚动高度。定位当前歌曲支持直接跳到尚未渲染的位置。多选、拖放和删除继续以完整队列为依据。

封面、歌词补全和播放状态变化局部更新共享歌曲数据。仍需完整读取曲库的事件合并处理；读取期间发生新变化时补读，避免较旧结果覆盖新变化。设置页保留数据，曲库变化后再刷新，缓存统计在重新进入且超过一分钟后刷新。

页面显示时使用 160 毫秒的淡入；切换立即完成，不等待退出动画，也不禁用交互。动画仅改变透明度，避免影响滚动容器、列表位置和弹窗定位。隐藏页面时取消动画。设置分类切换使用相同效果；播放器和侧栏不参与动画。

启动、首次读取歌手/专辑资料、缓存统计、备份列表和系统字体提供对应的占位效果。已有页面和资料刷新时继续显示缓存内容；占位只用于尚无数据的等待阶段，完成或失败后移除。缓存统计支持失败后重试。系统启用“减少动画”时，页面淡入和占位呼吸动画均关闭；占位内容仍可见。

## 验证

`scripts/verify-responsive-navigation.mjs` 纳入 Web 回归检查，使用 1,200 首歌曲和多个歌单，覆盖桌面和手机布局：

- 页面 DOM、搜索、排序、选择和滚动位置保留。
- 播放进度持续更新时导航栏没有 DOM 更新。
- 隐藏播放页停止频谱绘制，音频继续播放。
- 隐藏列表不响应全选快捷键。
- 歌词补全更新已保留页面，不读取整份曲库。
- 虚拟队列滚动到末尾、定位当前歌曲和详情数量限制。

单独运行这组检查：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
node --experimental-transform-types scripts/verify-web.mjs --responsive-only
```

自动检查使用浏览器及模拟桌面接口。长期运行的内存趋势、实际用户曲库和 Windows 原生窗口的切换感受仍需在桌面包中验证。

`scripts/verify-loading-feedback.mjs` 使用可控的延迟响应，覆盖桌面和手机布局的立即交互、搜索保留、减少动画、首次加载占位、保留原文刷新、错误/重试和启动加载。单独运行：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
node --experimental-transform-types scripts/verify-web.mjs --feedback-only
```
