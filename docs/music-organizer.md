# 曲库整理

入口：点击工具箱打开应用菜单，再点击「曲库整理」卡片。应用中可点击「返回工具箱」选择其他工具。支持本地音乐文件或多个文件夹路径，递归扫描子文件夹。浏览器开发模式可直接输入绝对路径；桌面版也可以选择文件夹或拖入路径。加密音频请先使用「格式还原」。

## 四项独立操作

| 操作 | 行为 |
| --- | --- |
| 按格式命名 | 使用 `{title}`（歌名）、`{artist}`（歌手）、`{album}`（专辑）、`{filename}`（不含扩展名的原文件名）生成文件名，保留音频扩展名。目标留空则在原位置重命名；指定目标则移入目标。 |
| 按歌手归档 | 根据本地标签在目标下创建歌手文件夹并移动音乐，保留原文件名，不同时重命名或去重。 |
| 清理重复音乐 | SHA-256 相同的文件为完全重复；标签中歌名、歌手、专辑相同的文件为候选重复；无完整标签时仅按同名识别疑似重复。已知时长相差超过两秒的版本不会直接匹配。逐组选择保留一个版本或全部保留。 |
| 合并多个路径 | 将所有来源下的音乐移动至目标文件夹，保留文件名，不同时按歌手归档、改标签或去重。 |

标签不完整时使用原文件名、未知歌手或未知专辑，并在预览中提示。非法文件名字符会替换，Windows 保留名称会加前缀。合唱歌手按完整的歌手标签归档，不擅自拆分。

## 预览与确认

1. 添加一个或多个来源，选择独立操作，按需填写目标与命名格式。
2. 点击「预览整理」。此步骤只读取文件，不改名、不移动。
3. 检查源路径、目标路径、附属文件与提示；去重时逐组选取保留版本。
4. 勾选确认，再点击「确认并执行」。改变来源或配置后必须重新预览。

每次最多扫描 5,000 首、100 个来源。预览在进程内保存，30 分钟后或重启后失效，最多保存最近八份。扫描显示发现阶段的歌曲数量，以及读取阶段的已处理数量、总数、当前文件、已读取字节和百分比。未知总数时显示不定进度，不虚报完成。可点击「取消扫描」，不会改名或移动文件。执行期间请勿关闭应用或编辑相关文件。

### 去重匹配方式

- **完整校验（默认）**：读取标签、音频参数和整个文件的 SHA-256，识别内容完全相同的文件，也列出元数据相同的候选版本。
- **快速匹配**：扫描阶段不打开音频或附属文件，只读取目录与文件属性。优先使用曲库内与当前文件大小、修改时间一致的已有歌名、歌手、专辑和时长；未入库、元数据不完整或已过期时，按同名与相同大小寻找疑似重复。只有大小相同、名称不同的文件不会直接归为一组。已有完整元数据相同但大小不同的版本仍会列为候选，便于选择不同音质。没有读取音频参数时明确显示未知，不能推断音质。
- 快速匹配不证明内容相同，全部候选组都必须由用户选择保留版本或全部保留，绝不自动预选。可能漏掉不同名称且没有可用曲库元数据的重复音乐。切换匹配方式会清除旧预览和确认状态。
- 快速预览的变更检查使用大小与修改时间，不能识别同时保持这两项不变的内容编辑；精确内容检查请用完整校验。执行移动时仍计算实际移动文件的完整校验值并校验目标副本，歌词、图片随行及恢复区机制不变。快速匹配只加速预览，不跳过执行时的复制安全校验。

同一目录的音乐与附属文件只索引一次，避免大量歌曲反复遍历同一目录。完整校验按块读取，可在大文件读取过程中取消。

FLAC 显示采样率、位深、声道和无损属性，PCM WAV 显示采样率、位深、声道，MP3 显示采样率和首帧码率（不将其视为 VBR 的平均码率）。其他格式或无法读取的参数明确显示未知，不根据文件大小或扩展名断言音质高低。只有内容完全相同的组预选一个文件；其他组必须由用户选择，不会自动选择所谓「最高音质」。本工具不进行音频指纹匹配，候选组可能包含不同演唱版本，应核对后处理。

## 歌词、图片与重名

自动匹配同文件夹下与音频同名的 `.lrc`、`.srt`、`.vtt`、`.txt`、`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.bmp`，名称与扩展名匹配不区分大小写。支持 `song.lrc` 和 `song.mp3.lrc` 两种命名形式。

重命名或移动音频时，附属文件使用相应的新名称与位置。若同一文件夹存在 `song.mp3` 和 `song.flac` 共用 `song.lrc`，只复制该歌词并保留源文件，避免另一版本失去歌词。通用的 `cover.jpg`、`folder.jpg` 等不与歌曲同名的共享图片不会擅自移动。

任意音频或随行附属文件的目标名称冲突，整组文件共同加 `(2)`、`(3)` 等序号，不覆盖已有文件。目标已在预览后出现同名文件、源文件改变（完整校验检查内容；快速匹配检查大小与修改时间）、附属文件新增或共用关系改变时拒绝执行，要求重新预览。不会跟随扫描中的符号链接；执行时也会核对目标路径，防止预览后被替换为符号链接。

## 安全与恢复

移动采用「独占创建目标 → 复制与 SHA-256 校验 → 更新曲库事务 → 移除来源 → 提交事务」。适用于跨磁盘整理，但需要暂时容纳整批复制文件的空闲空间。处理失败或请求取消会回滚已完成的文件操作和曲库事务；无法自动恢复的文件会保留副本并明确提示操作记录的位置。

去重不会永久删除。未选中的音频及其附属文件移入各自源文件夹的 `.luma-organizer-recovery/<操作编号>/`。被保留版本的歌词和图片不覆盖、不合并；其他版本的独有附属文件仍在恢复区。恢复区在整理预览、文件夹导入与曲库扫描中自动排除，避免重新导入重复音乐。需要恢复时可通过文件管理器把相应文件移回原位置，再重新扫描曲库。

操作记录保存在应用数据根目录的 `organizer-history/<操作编号>.json`，包含原位置、新位置、复制/移动标志、文件校验信息与状态。完成界面显示具体路径。进程被强制结束或机器断电不等同于普通失败，文件系统与 SQLite 无法跨介质原子提交；出现 `pending` 或 `recovery-required` 状态时请根据记录检查两端文件并恢复，切勿直接清空恢复区。

已入库歌曲改名、移动后保留 ID，歌单和收藏继续有效。去重时将歌单、收藏、播放记录、队列和自定义标签合并到被保留歌曲，前端同步更新。未入库的音乐不会因为整理而自动加入曲库，临时播放歌曲只同步路径。

## 验证

`go test ./backend -run '^TestOrganizer' -count=1` 覆盖四项操作、大小写扩展名、歌词/图片随行、共用文件、重名保护、音质选择、恢复区排除、关系合并、预览变更、过期、请求取消、数据库失败回滚、临时歌曲及 API 输入校验。
