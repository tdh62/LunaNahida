# 可选的加密音乐还原模块

播放器内的「格式还原」由独立的 `LunaNahida.Converter.exe` 提供，负责现有 NCM、QMC、KGM、KWM、TM、XM 等加密文件的还原。它保留解码出的原始音频格式，不提供音频转码。某些文件仍可能需要额外密钥，后缀支持不代表每个文件都能还原。

## 安装、更新与移除

退出播放器，把模块包中的 `modules` 文件夹复制到 `LunaNahida.exe` 所在目录：

```text
LunaNahida.exe
modules/
  music-restore/
    LunaNahida.Converter.exe
    README.txt
    LICENSES/
```

重新启动后，工具箱显示「格式还原」，设置显示「自动转换加密音频」「备份加密源文件」及手动扫描的备份选择。便携版将同一 `modules` 目录放在便携版 EXE 旁边，不能放进 `userdata` 或 WebView2 目录。

更新前先退出播放器，再替换整个模块目录。移除时退出播放器，删除 `modules/music-restore` 即可。没有模块、模块无法运行或协议不兼容时，播放器正常启动，相关入口和设置自动隐藏；普通歌曲播放、导入和扫描继续可用。

确认模块不可用后，原先开启的自动转换会保存为关闭。重新安装模块不会自动重新开启，需在设置中手动打开。原来的备份偏好保留。已经还原的歌曲不依赖该模块，可以继续播放。

运行期间重新切回窗口或打开工具箱、设置时会刷新能力；若模块异常，服务端也会拦截调用，不依赖界面隐藏。混合拖入普通歌曲和加密歌曲时，缺模块的加密歌曲会汇总提示跳过，普通歌曲仍按原来的方式处理；迷你播放器遵循相同规则。

## 播放器内还原

还原结果仍输出至原文件夹；目标或备份已有同名文件时不会覆盖。保留源文件备份时，原文件放入同目录的 `.lunanahida-original-backup`。关闭备份时，成功发布结果后清理原文件。已入库歌曲保留原 ID、收藏和歌单关系。

模块只生成暂存结果。主程序验证音频和源文件变更情况后才处理源文件，再更新曲库。解码失败、模块崩溃或请求在解码阶段取消不会移动或删除源文件；退出播放器会停止模块及它启动的子进程。

操作记录暂存在源目录的 `.lunanahida-convert-job-<随机值>/operation.json`，任务位置同时登记到本机数据库。正常成功后清理；曲库更新、文件恢复或清理失败时保留记录，结果提示具体路径。这些任务目录不会被曲库扫描、导入或整理工具再次处理。

批量还原显示已处理数量和总数。点击「取消还原」停止当前解码和后续任务；已经完成文件发布的操作会完成当前文件收尾并返回结果，成功结果保留。取消后可「继续剩余任务」，单个失败不阻止其余文件，结束后可「仅重试失败项」。进度按文件数量计算，不表示当前文件的解码百分比。批次列表保留在当前会话，重启后的文件恢复使用下述操作记录。

## 中断任务恢复

打开「工具箱 → 文件恢复」，会检查本机登记的任务和仍可访问的监听文件夹。「检查其他文件夹」可发现旧版本、其他安装或数据库丢失后遗留的任务。文件恢复不需要还原模块；缺模块时「格式还原」入口仍隐藏。

- 「恢复源文件」核对源文件副本的 SHA-256，再复制回原路径。原路径已有文件时另存为 `<源路径>.recovered-encrypted`；该恢复副本也已存在时停止，不覆盖。加密源副本与还原结果均保留。
- 「重新入库」核对还原结果的 SHA-256 和音频头，再加入曲库。任务登记时已入库且仍关联该源路径的歌曲保留原 ID、收藏与歌单关系，手动编辑的歌曲信息继续保留。恢复时保留原文件副本，即使原设置关闭了备份。
- 两项操作均需界面确认；文件改变、链接路径、越界路径、同名冲突或记录损坏时停止，保留文件，可「打开文件夹」人工检查。

恢复完成的记录会标记为已处理并从列表隐藏，任务目录和文件副本继续保留，便于人工核对。解码阶段中断时源文件尚未处理，重新添加源文件即可。旧版记录缺少文件校验信息，只提供检查，不自动移动文件。不要直接删除可能包含唯一文件副本的任务目录。

MP3/FLAC 的标题、歌手、专辑及封面沿用已有写入方式。其他原始格式保留原有可选 FFmpeg 标签处理；模块本身不要求安装 FFmpeg，播放器也可以使用模块返回的元数据展示歌曲。

## 独立命令行使用

```powershell
.\LunaNahida.Converter.exe restore "C:\Music\song.ncm" --output-dir "C:\Restored"
```

独立使用不需要播放器、数据库、Go、Node.js 或 WebView2，默认保留源文件。输出重名会失败；源文件与还原结果同名时，需要指定不同输出目录。独立 EXE 提供命令行入口，播放器继续提供图形界面。

## 构建与分发

| 命令 | 产物 |
| --- | --- |
| `corepack pnpm build:converter` | `bin/converter/modules/music-restore`，可单独分发 |
| `corepack pnpm build:desktop` | `bin/LunaNahida.exe` 及原有字典，不包含还原模块 |
| `corepack pnpm build:desktop:full` | 桌面主程序、字典及 `bin/modules/music-restore` |
| `corepack pnpm build:portable` | 原有便携包，不包含还原模块 |
| `corepack pnpm build:portable:full` | 便携包及 `bin/portable/modules/music-restore` |
| `corepack pnpm build:release` | `bin/releases/<版本>/`：精简版、完整版、独立模块三个 ZIP，以及校验值和发布清单 |
| `corepack pnpm build:release:portable` | 上述三个 ZIP，另附便携精简版和便携完整版 ZIP；需要本地 WebView2 固定运行环境 |

版本统一来源为 `internal/buildinfo/VERSION`。修改后执行 `corepack pnpm build:version` 同步前端包版本和 Windows 资源描述，`check:version` 检查是否一致。Windows 构建会重建 EXE 的版本、图标与清单资源，需要安装与项目匹配的 Wails CLI：`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.26`。协议版本单独管理，应用版本变化不意味着协议变化。

发布构建从专用暂存目录生成包，不读取已有便携版的 `userdata`。每个 ZIP 包含 `README.txt`、安装说明、`MANIFEST.json`（各文件大小与 SHA-256）。发布目录中的 `SHA256SUMS.txt` 校验完整 ZIP，`release.json` 记录应用版本、模块协议与文件清单。独立模块 ZIP 的 `modules` 可直接解压到播放器 EXE 旁。相同包内容生成一致的 ZIP；Go 工具链或构建内容变化仍可能使 EXE 和 ZIP 校验值变化。

先生成完整包、再构建精简包时，构建脚本会移除输出目录中残留的还原模块；便携版 `userdata` 保留。模块包应整体分发，包含 `README.txt` 和 `LICENSES`。

开发前可先构建模块，`cmd/devserver` 自动定位 `bin/converter/modules/music-restore`。开发环境也可通过 `LUNANAHIDA_CONVERTER` 指定模块 EXE 的绝对路径；生产版忽略该覆盖，始终使用主 EXE 旁边的固定目录。

## 实现与验证

主程序通过版本 1 JSON 协议按需启动子进程，不打开新的网络端口、不常驻转换服务。模块只有解码、标签和文件输出逻辑，不能访问播放器数据库；主 EXE 的生产依赖图不包含 `unlock-music` 解码器。

`go test ./...` 覆盖真实还原样本、缺模块导入及扫描、协议/文件路径异常、独立使用、模块卸载重装、重名保护、重启恢复、文件篡改、原 ID 与收藏保留、提前及执行中取消、分发包清单与用户数据排除。Windows 测试还验证取消和退出会终止后代进程。前端测试和 `test:web` 验证能力开关、入口及设置隐藏、主/迷你窗口混合拖入、恢复确认、批量进度、取消、继续及失败项重试。
