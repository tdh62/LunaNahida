# 加密音乐还原模块拆分设计

状态：核心方案已实施；此文保留拆分设计及验收依据，实际安装、构建和使用方式见 [加密音乐还原模块](music-restore.md)。范围只包含现有加密音乐文件还原，不增加音频转码或音质选择。

## 1. 目标与推荐方案

把现有解码、原始音频识别及标签写入移入独立的 `LunaNahida.Converter.exe`。播放器通过子进程调用它；模块不存在或无法使用时，隐藏「格式还原」及相关设置，并停止所有入口的还原操作。普通音乐的播放、导入、监听和扫描继续可用。

推荐第一版采用同一仓库、两个构建入口、版本化 JSON 通信。每首文件按需启动一个子进程，完成后退出；沿用当前串行转换方式。独立 EXE 也提供命令行入口，便于单独分发和使用。

```text
LunaNahida/
├── LunaNahida.exe
├── search-dict/
├── modules/
│   └── music-restore/                   # 整个目录可选
│       ├── LunaNahida.Converter.exe
│       ├── README.txt
│       └── LICENSES/
└── WebView2/                            # 便携版原有运行时
```

用户退出播放器后，将模块目录放入对应位置，重新启动即可识别；删除目录再启动，功能自动关闭并隐藏。播放器与模块可以分别打包、更新。第一版的独立使用方式为命令行，播放器内继续使用现有图形界面；独立图形应用不属于这次拆分。

## 2. 当前实现与需要拆开的关联

| 位置 | 当前行为 | 拆分时的处理 |
| --- | --- | --- |
| `backend/conversion.go` | 同时负责解码、标签写入、源文件备份、输出发布和曲库更新 | 拆成解码引擎、进程客户端和主程序编排 |
| `encryptedFile()` | 依赖第三方解码器注册表判断格式 | 改为不依赖解码器的轻量分类规则 |
| `backend/library.go` | 导入、自动扫描调用 `Store.Convert()`；手动扫描临时强制开启转换 | 每条路径检查模块能力；手动扫描不能绕过 |
| `backend/api.go` | 提供格式检查、转换接口，能力接口尚无转换状态 | 增加模块能力和不可用错误；保留只读格式检查 |
| `src/components/Toolbox.tsx` | 「格式还原」卡片始终注册；工具箱拖入会打开还原面板 | 按能力过滤卡片，拦截拖入和启动请求 |
| `src/pages/Index.tsx` | 主窗口拖入打开还原面板；迷你播放器拖入直接转换 | 两种窗口都检查能力，混合文件仍处理普通音频 |
| `src/components/PlayerSettings.tsx` | 展示自动转换、源文件备份及手动扫描备份选项 | 不可用时移除相关设置，保留扫描按钮 |
| `src/lib/runtime.ts`、`src/hooks/use-runtime.tsx` | 启动时获取一次能力信息 | 增加转换状态及局部能力刷新 |
| `scripts/build-desktop.mjs`、`scripts/build-portable.mjs` | 只构建主 EXE | 增加独立模块构建和明确的可选装包参数 |

现有测试已经覆盖 QMC/NCM、标签与封面、输出重名、备份、曲库 ID、自动导入及手动扫描，应作为拆分后的行为基线。

## 3. 职责边界

```mermaid
flowchart LR
    UI[播放器界面] --> Host[主程序：能力检查和任务编排]
    Host --> Worker[转换 EXE：解码和写入标签]
    Worker --> Stage[暂存音频和元数据]
    Stage --> Commit[主程序：验证、备份和发布]
    Commit --> DB[曲库更新]
```

**主程序负责：** 确认模块状态、规范化来源路径、排队、选择备份策略、创建任务目录、验证输出、处理目标冲突、备份或清理源文件、更新 SQLite 和播放器队列。`Store.Convert()` 保留作为所有还原入口的统一编排入口。

**转换 EXE 负责：** 加载 `unlock-music` 解码器、验证输入、还原音频字节、识别实际输出格式、提取 NCM/QQ 来源信息、写入现有标签及封面、将结果写入指定任务目录。内部仍按解码器注册顺序尝试同一后缀的多个解码器。

内部调用模式只读取源文件、写入任务目录，不修改源文件、不访问播放器数据库，不决定是否加入曲库。这样模块崩溃或返回异常时，播放器可以直接舍弃暂存结果，源文件不会因解码阶段失败而被移动。

第三方类型 `common.AudioMeta` 不跨进程，也不留在主程序接口中。转换为自有结构：`title`、`artists`、`album`、`provider`、`providerId`、`coverFile`。封面文件保存在任务目录，主程序继续负责写入封面缓存及尊重已有手动编辑信息。

MP3/FLAC 的现有标签写入随解码器移入模块。当前其他格式可选使用 FFmpeg 写标签的路径仍属于还原后的标签处理，不增加重编码；基础模块不要求分发 FFmpeg，也不能因缺少它而隐藏整个还原功能。是否成功写入这类标签通过结果提示，曲库仍可使用返回的元数据。

## 4. 模块发现与可用性

发行版只检查 `os.Executable()` 所在目录下的固定模块路径，不从工作目录或系统 PATH 自动寻找同名程序。开发服务使用显式的开发配置指向构建产物，因为 `go run` 的 EXE 位于临时目录；该覆盖入口不纳入发行版自动发现。

发现文件后执行一次只读握手：

```text
LunaNahida.Converter.exe --describe
```

```json
{
  "module": "LunaNahida.MusicRestore",
  "protocol": 1,
  "version": "1.0.0",
  "operations": ["restore"],
  "classificationRevision": 1
}
```

握手限制为 1 秒，输出不超过 256 KiB；验证模块标识、协议、操作及分类规则版本。协议匹配即可独立更新模块，不要求与主程序版本号完全相同。缺文件、启动失败、超时、无效 JSON、协议或分类规则不兼容，都降级为不可用；记录原因，播放器正常启动。

握手结果缓存；批量导入和扫描不能每遇到一首歌曲都执行握手。每次实际转换前检查文件状态，变更后重新握手。第一版保证重启后的安装/移除识别；运行期间在窗口重新获得焦点、打开工具箱或设置时做节流检查，能力刷新失败不能阻断播放。

模块文件缺失、启动失败及协议错误会更新为不可用；某首文件损坏、需要额外密钥或不支持其内容，属于单文件失败，不能据此隐藏整个功能。

删除正在运行的模块在 Windows 上可能被文件占用限制。更新和卸载说明明确要求先退出播放器。

## 5. 通信与独立使用

内部模式：

```text
LunaNahida.Converter.exe --worker
```

主程序直接创建子进程，通过标准输入发送一个 JSON 请求，通过标准输出读取一个 JSON 结果；标准错误只写日志。Windows 使用现有隐藏子进程窗口的方式。转换 EXE 使用普通控制台构建，使单独命令行使用仍能获得输出。

```json
{
  "protocol": 1,
  "requestId": "任务唯一编号",
  "operation": "restore",
  "source": "C:\\Music\\song.ncm",
  "workDir": "C:\\Music\\.lunanahida-convert-job-随机值"
}
```

```json
{
  "protocol": 1,
  "requestId": "任务唯一编号",
  "status": "ready",
  "audioFile": "audio.flac",
  "sourceSuffix": ".ncm",
  "extension": ".flac",
  "metadata": {
    "title": "歌曲名",
    "artists": ["歌手"],
    "album": "专辑名",
    "provider": "ncm",
    "providerId": "123456",
    "coverFile": "cover.jpg"
  },
  "warnings": []
}
```

`ready` 只表示暂存结果可供验证，最终的 `converted` 状态由主程序完成文件发布后产生。转换失败返回 `status: "failed"`、稳定的 `code` 和可读的 `message`。进程非零退出、没有完整响应、请求编号不匹配或结果越界均视为失败。

音频和封面不通过 JSON 传输。协议响应限制为 256 KiB，日志采用有上限的缓冲；封面沿用当前 15 MiB 上限。返回路径必须是任务目录内的相对文件名，拒绝目录穿越及链接；输出扩展名必须在允许的原始音频格式中。最终文件名由主程序根据源文件及匹配的完整后缀计算。

请求取消和播放器退出时终止当前转换进程及其可能启动的标签处理子进程，等待退出后清理暂存目录。Windows 需要通过 Job Object 管理进程树，仅取消 `exec.CommandContext` 不能保证所有后代进程退出。导入链应传递任务上下文，替换当前 `context.Background()`，让取消可以到达转换任务。

独立命令行入口建议为：

```text
LunaNahida.Converter.exe restore "C:\Music\song.ncm" --output-dir "C:\Restored"
```

独立模式默认保留源文件，目标重名直接失败。它复用同一解码引擎及文件发布组件，不依赖播放器、SQLite 或 WebView2。第一版不提供删除源文件的独立命令行选项；播放器内已有备份选择继续由主程序管理。

## 6. 源文件与曲库提交

保留现有「输出至原文件夹」「不覆盖目标」「源文件备份目录」及「已入库歌曲保留 ID」规则，执行顺序如下：

1. 主程序检查能力和源文件，创建源文件同目录下的唯一任务目录；保存源文件身份及变更信息。
2. 模块还原到任务目录，完成标签写入并关闭全部文件句柄。
3. 主程序核对响应、音频格式、输出文件、源文件是否变化、目标及备份是否冲突；取消或失败时只清理暂存结果。
4. 写入任务操作记录，再把源文件移入备份目录，或暂存为待清理文件；同扩展名还原也执行这一流程。
5. 发布输出时独占创建目标，避免覆盖；失败时尝试恢复源文件，恢复失败则保留恢复文件并返回其位置。
6. 更新已有曲库路径或按请求导入新歌曲，保留原 ID、收藏及歌单关系，应用来源信息和元数据。
7. 完成后清理无须保留的源文件及任务目录。曲库更新失败时保留已经生成的音频，并返回「还原成功，曲库更新失败」，不把成功输出删除。

任务目录必须被曲库导入、扫描、格式检查及整理工具排除，避免并行扫描误读半成品。操作记录至少包含源路径、目标路径、源文件暂存/备份路径及 `staging`、`source-retired`、`published`、`completed` 状态。异常退出后未完成记录应能定位恢复文件，不自动删除仍可能包含唯一副本的目录。

文件系统操作和 SQLite 不能跨资源原子提交；正常失败执行回退，断电或进程强制终止依靠操作记录恢复。不能把现有 `os.Rename()` 序列视为完全原子操作。

## 7. 模块缺失时的产品行为

能力接口增加 `conversion: boolean`，表示模块实际可用，而非仅检查文件存在。诊断原因保存在后端；前端所有入口以同一个能力值为准。旧服务未返回该字段时按 `false` 处理。

| 场景 | 可用时 | 不可用时 |
| --- | --- | --- |
| 工具箱 | 显示「格式还原」 | 移除卡片；其他工具继续显示 |
| 自动转换、源文件备份设置 | 显示现有选项 | 从组件中移除，设置搜索也不再收录 |
| 手动扫描 | 保留现有一次性备份选择与还原行为 | 隐藏备份选择，扫描普通音乐；文案去除转换数量及还原说明 |
| 主窗口拖入/打开 | 沿用还原面板及自动转换规则 | 不打开还原面板；处理普通文件，加密文件仅作一次汇总提示 |
| 迷你播放器拖入 | 沿用还原并加入队列的行为 | 不调用转换；普通音乐仍入库及入队，保持迷你窗口 |
| 启动/定时扫描 | 尊重自动转换设置 | 跳过加密文件，继续扫描普通音乐，不反复弹出模块缺失提示 |
| 已还原歌曲 | 正常使用现有音频 | 正常播放、读取来源信息和封面，不依赖模块 |
| 直接请求转换 API | 正常编排 | 返回 HTTP 503 及 `CONVERTER_UNAVAILABLE`，不能触发备用内置解码 |

**自动关闭策略：** 确认不可用时，将已保存的 `autoConvert` 归一化为 `false`，同时所有执行路径仍强制检查模块能力。设置更新及备份恢复不能绕过检查；模块重新安装后显示入口，自动转换由用户重新开启。`backupOriginal` 保留既有偏好，但不可用时不显示。这样补装模块不会意外触发一批自动还原。

能力变成不可用后，前端停止接受新还原任务；空闲的还原面板返回工具箱并清理待处理队列。正在执行的任务先结束或失败，显示结果后再退出还原面板，不能丢弃已经生成的歌曲或误报成功。能力刷新只更新相关状态，不重建播放器或重复加载启动播放状态。

现有 `/api/scan` 要求 `backupOriginal` 必填，可以暂时保持请求契约：模块缺失时后端忽略该选项，前端传入已有偏好，但隐藏选择控件。关键是把手动扫描强制转换条件改为「手动扫描且模块可用」。

## 8. 模块缺失时仍能识别加密文件

主程序仍需要轻量分类能力，否则混合拖入中的加密文件可能被当成普通文件，`.mp3` 等伪装扩展名也可能直接进入播放队列。分类不应调用转换 EXE。

建立自有的格式描述表，仅保存后缀与文件头匹配规则，不引用解码器代码。覆盖当前注册表中的格式及变体，包含 `.kgm.flac`、`.vpr.flac` 等完整后缀；匹配优先级为完整加密后缀，再检查普通后缀的 `ifmt` 文件头，最后判断普通音频。不能只看 `filepath.Ext()`，也不能对所有以 `.flac` 结尾的加密格式都要求 `ifmt` 头。

分类表与解码器实际能力进行一致性验证，使用握手的 `classificationRevision` 拒绝主程序不能正确分类的新规则版本。单文件最终能否还原仍由模块验证，后缀匹配不保证解码成功。

保留 `/api/conversion/inspect` 作为兼容的只读文件分类接口，模块缺失时也能返回候选路径，并附带 `available: false`；它不执行转换、不启动外部程序。前端据此拆分混合文件，显示「已跳过 N 个加密音频文件，未安装还原模块」，继续导入普通文件。只有加密文件时显示提示并结束，不创建待处理任务。

直接后端导入也必须保护普通音频：混合文件或文件夹跳过无法处理的加密项，保留现有普通歌曲数组响应；单独导入一个加密文件则返回明确错误。已入库但尚未还原的文件不能仅因模块缺失被删除，缺失判断仍依据真实文件存在情况。

## 9. 建议的代码结构与分发

```text
cmd/music-restore/main.go                # --describe / --worker / restore
internal/musicrestore/                  # 解码、原始格式识别、标签写入
internal/restoreprotocol/               # 自有协议、元数据和错误码，无第三方解码依赖
internal/restoreformats/                # 轻量分类和输出文件头识别
internal/restorefiles/                  # 无数据库的发布、冲突及恢复记录组件
backend/converter_client.go             # 发现、握手、子进程与能力缓存
backend/conversion.go                   # Store.Convert：编排和曲库更新
scripts/build-converter.mjs             # 单独构建并复制许可证及模块说明
```

`internal/musicrestore` 只能被转换命令和它的测试引用；主程序不得间接导入它。同一 Go module 足够实现两份独立二进制，暂不拆成两个仓库或引入 Go 动态插件。

保留第三方源码供模块构建使用；主程序的依赖图必须不含 `unlock-music.dev/cli/algo/*` 和只被解码器使用的依赖。主程序仍需要读取普通音频标签，不能为了拆分而移走其正常播放/元数据功能使用的依赖。

建议新增 `build:converter`，单独输出模块目录；`build:desktop` 和 `build:portable` 默认不装入模块，增加明确的 `--with-converter` 参数生成含模块的完整包。生成发行包时使用明确的文件清单，避免上一次构建残留模块被误打入精简包；不要为清理构建目录而删除便携用户的 `userdata`。

模块包包含使用说明、模块/协议版本，以及仓库内 `third_party/unlock-music/LICENSE` 和实际分发依赖的许可证。基础还原模块不要求安装 Go、Node.js 或 WebView2。

## 10. 实施顺序与验收

1. 提取自有元数据结构、分类规则及无数据库的解码引擎，先保持现有还原结果。
2. 增加模块 EXE、协议和主程序客户端，把 `Store.Convert()` 切换到子进程，移除主程序解码器引用。
3. 接入能力、设置归一化及所有入口保护，再调整界面隐藏和混合导入提示。
4. 增加模块独立构建、可选装包及恢复记录，验证精简包、完整包和独立命令行使用。

| 验收项目 | 必须满足的结果 |
| --- | --- |
| 模块存在、缺失、损坏、握手超时、协议不匹配 | 主程序均正常启动；仅真正可用时显示还原功能 |
| 删除模块后旧设置仍为自动转换开启 | 后端关闭该偏好；启动、定时及手动扫描都不执行还原 |
| 主窗口和迷你窗口混合拖入 | 普通音乐继续处理；缺模块时加密歌曲不弹还原面板、不进队列 |
| 工具箱拖入、启动请求、设置搜索、旧页面状态 | 不能绕过隐藏或打开不可用的还原面板 |
| 直接调用转换 API、后端导入及手动扫描 | 服务端自身检查能力，不能仅靠界面阻止 |
| 当前格式、复合后缀、`ifmt` 伪装格式 | 分类不依赖模块，正确区分普通与加密音频 |
| NCM/QMC 及现有样本 | 原始音频、标签、封面及来源信息保持一致 |
| 重名、备份重名、同扩展名、中文与空格路径 | 不覆盖；成功保留既有文件和曲库身份规则 |
| 模块崩溃、无响应、非法返回路径、取消和播放器退出 | 不发布半成品；解码失败不改变源文件；停止并清理进程树 |
| 发布后曲库更新失败、恢复失败、异常中断 | 保留可用副本，返回可定位的提示与操作记录 |
| 无模块扫描遇到已入库加密文件 | 不因能力缺失错误删除已有歌曲记录 |
| 普通播放、组织曲库、Web 模式 | 不依赖转换模块，不新增外部进程调用 |
| 精简主 EXE 依赖检查 | `go list -deps .` 无解码器包；实际精简包无模块残留 |
| 独立模块命令行 | 无播放器、数据库及 WebView2 也能还原，默认保留源文件 |

引擎测试复用现有真实样本；客户端测试使用可控的伪模块覆盖协议与进程失败，另做真实 EXE 集成测试。前端与浏览器验证覆盖 `conversion: true/false` 两种能力，并更新已有迷你拖入测试的能力桩。

完成标准是两个可分别分发的产物，以及「有模块可用、无模块自动关闭并隐藏」的完整行为。实施代码和验证入口已加入仓库，具体使用方式以模块说明为准。
